# 图标说明

## 应用图标：像素画鲸鱼娘

**形象来源**：用户提供的像素画原图 `source-pixel-maid.png`（901×1280，白底）。
用户明确表示这张图可以用（本轮对话中确认为「A. 这张图你可以使用」）。

不是本项目手绘的，也不是从游戏里提取的——是用户指定并授权使用的同人像素画。

### 产物

| 文件 | 用途 |
|---|---|
| `source-pixel-maid.png` | **原始素材，不要动**。所有尺寸都由它生成 |
| `app-icon.svg` | 内嵌 256px PNG 的 SVG，打包与渲染统一走它 |
| `app-icon-256.png` | README / 文档引用 |
| `preview-{128,64,48,32,16}.png` | 各尺寸人眼检查用 |
| `desktop/icon.ico` | 16/32/48/64/128/256 六尺寸，PyInstaller 打进 exe |
| `android/.../drawable/ic_launcher_{background,foreground,monochrome}.png` | 安卓自适应图标三层（432px） |
| `android/.../mipmap-*/ic_launcher{,_round}.png` | 安卓各密度兜底（48/72/96/144/192），老启动器与部分国产 ROM 必须有 |

### 怎么重新生成

```
server\.venv\Scripts\python.exe assets\make_icon_from_source.py
```

脚本做四件事，**不做任何重绘**：

1. **抠白底**：只去掉与画布边缘连通的白色（角色内部的白蕾丝、白围裙不动）
2. **裁上半身**：`CROP = (40, 10, 830, 900)`，把女仆头饰、双马尾、脸、金色胸针、
   围裙上的小鲸鱼都包进来
3. **留安全边**：主体占画布 90%，安卓圆形遮罩下不会被裁
4. **分档缩放**：≥128px 用 LANCZOS 平滑；<128px 用 NEAREST 保住像素硬边
5. **安卓另出两套**：自适应图标三层（`drawable/`）+ 五档密度兜底（`mipmap-*/`）

### 手机端为什么必须两套都要

自适应图标只放在 `mipmap-anydpi-v26` 时，**部分国产 ROM 的启动器找不到对应密度的
PNG，会回退成系统默认图标，或者一直显示缓存的旧图标**。所以额外生成
48/72/96/144/192 五档 `ic_launcher.png` 与 `ic_launcher_round.png`：
- 新系统走自适应图标（能跟随系统形状、支持主题单色）
- 老启动器 / 缓存旧的走 PNG 兜底

### 为什么小尺寸要单独处理

原图是细密像素画（每格约 11px）。直接 LANCZOS 缩到 16/32px 会糊成一坨蓝，
所以小尺寸改用 NEAREST，至少保住「蓝发 + 白头饰 + 浅蓝底」的轮廓。

### 已知局限

- **16px 下只能看出是蓝发小人**，五官必然丢失——这是像素画缩到 16px 的物理极限
- 裁切框是硬编码的像素坐标。如果换一张原图，需要重新量 `CROP`

## 历史记录（2026-11-07）

图标这块前后试过三版，留个记录避免以后再绕：

| 版本 | 做法 | 结论 |
|---|---|---|
| v1 | 自绘矢量：圆头 + 女仆帽 + 手柄 | 用户反馈「像戴头箍的蛋」，推翻 |
| v2 | 自绘矢量（加双马尾、围裙、蕾丝帽） | 元素齐了，但仍不是参考图的像素风 |

| **v4（当前）** | **直接用用户提供的像素画原图做抠图 + 裁切** | 采纳 |

## 装到手机还是旧图标？

Android 会把启动器图标缓存很久。换图标后如果桌面还显示旧的：

1. **先卸载再装**（包名 `com.afu.controller` 没变，覆盖安装通常也行，但缓存可能不清）
2. 重启手机，或在「设置 → 应用 → 阿福代肝控制器 → 存储」里点「清除缓存」
3. 换一个启动器主题再换回来，逼它重新读图标

这不是程序的问题，是启动器的图标缓存机制。
