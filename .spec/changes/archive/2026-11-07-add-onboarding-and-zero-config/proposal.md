# 变更：新用户可用性与零配置自适应

## 动机

当前应用是「只为作者这台机器写的」：

- 界面上的地址、端口、数据路径都按作者的机器写死（`PORT = 8765`、`192.168.1.10:8765` 直接写在代码和占位符里）
- 数据目录依赖 `F:\...` 之类的本机布局，换台机器就找不到
- 没有任何面向新用户的说明。新用户解压后看到的是「⚠ 缺少组件」，不知道缺的是 MAA 还是 MuMu，也不知道去哪装
- 「打开网页」实际是白屏：`/docs` 依赖境外 CDN 的 swagger 静态资源，实测 5 秒才响应
- 公网隧道有 bug：监控线程每 10 秒重复拉起 cloudflared，日志里堆满重复的「已启动 cloudflared」，公网地址反复变化，手机上保存的地址必然失效

这五条直接挡住了开源。别人拿到代码跑不起来，也就谈不上用。

## 范围

在范围内：

- 依赖清单页：逐项列出游戏与工具、是否就绪、官网链接
- 首次启动引导：许可、依赖检查、连接方式，可跳过，状态持久化
- 缺失依赖时的可读提示（缺哪一项、去哪获取）
- 端口自适应：首选端口被占时自动换端口，界面上显示实际端口
- 连接地址自动探测并排序展示，去掉所有写死的 IP / 端口
- 数据目录跟随可执行文件，只读时降级到用户目录并说明
- 修复隧道重复启动 bug，地址变化时明确通知
- 缺 cloudflared 时降级为仅局域网并说明
- 内置可离线渲染的网页控制台，替换依赖 CDN 的 Swagger 白屏
- 面向新用户的 README（前置要求 + 官网链接 + 排障）

不在范围内：

- 桌面端与手机端的**视觉重做**（左侧栏、卡片、深色主题、原创图标）——那是下一个变更 `polish-ui-and-mobile-ux`
- 手机 APP 底栏游戏图标、返回手势处理——同上
- 自动下载安装 MAA / MuMu / BetterGI / 游戏——本变更只给链接，不代劳
- 自动更新、代码签名、安装包制作
- 多用户、多台手机同时连接的管理

## 方法

把「配置从代码里拿出来」：所有端口、路径、地址改为运行时探测并落盘配置，数据目录统一由入口决定。同时新增一个依赖清单配置（纯数据），供桌面界面、手机端提示、README 三处共用同一份事实，避免说法不一致。

网页部分不再用 FastAPI 默认的 Swagger UI（它把资源指向 CDN），改为服务端自带的静态页面，资源随包分发。

隧道 bug 是监控线程在 `_watch` 里重复进入 `start()` 且没有防重入，改为单一状态机：同一时刻最多一个 cloudflared 进程，退出后只重启一次。
