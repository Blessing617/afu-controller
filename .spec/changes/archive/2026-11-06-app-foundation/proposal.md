# 变更：游戏编排 APP 基座搭建

## 动机

现在跑三个游戏的日常需要人坐在电脑前，手动打开各自的小助手点「开始」。想把它变成：**手机带出门，点一下就能让家里的电脑跑起来**。

前置调研（`docs/00`–`docs/05`）已经把三条链路都验证过了：MAA 一键长草、星铁 `m7a.exe daily`、原神 `BetterGI.exe --startOneDragon` 都能被外部程序触发，且「服务以计划任务常驻高权限」的模型也跑通了。缺的是一个真正可用的两端应用：

- 手机端：能连上电脑、能看到三个游戏、能一键开始
- 电脑端：能被远程访问、能自己找到游戏和工具装在哪、能执行并回报状态

这一版只搭**基座**——把「连得上 + 找得到 + 点得动」跑通，异常自愈、定时、多账号留到后面。

## 范围

在范围内：
- 电脑端常驻服务（Python），监听 `0.0.0.0`，通过 **Tailscale** 被手机跨网络访问
- 配对鉴权（一次性配对码换长期 token）
- 自动探测游戏与工具路径（注册表 + 已知登记文件 + 常见目录有限扫描），支持手动覆盖
- Android APP（Kotlin + Compose，设计语言参考 `afu-ledger`）
- 电脑端桌面应用（双击启动、显示状态与配对码、常驻），替代命令行脚本
- 三个游戏页（明日方舟 / 原神 / 星穹铁道），每页一个「开始」按钮触发对应一条龙
- 前台任务互斥、任务状态回传（运行中 / 成功 / 失败 / 用户停止）
- 启动前置检查：锁屏、工具缺失

不在范围内：
- iOS / 鸿蒙 / 桌面端 APP
- 定时调度、体力阈值自动启动、多账号
- 完整的异常自愈（更新弹窗自动点、背包满自动跳过等，这些列入 `docs/05` 后续迭代）
- 公网暴露（不使用 frp / 端口映射；只走 Tailscale 虚拟内网）
- 局域网自动发现（mDNS / UDP 广播）——统一用 Tailscale 固定地址，同 WiFi 下 Tailscale 本身会走直连，不需要额外区分
- 录制 / 回放、自定义脚本编排

## 方法

电脑端重写一份正规服务（当前 `server/probe/maa_probe.py` 只是验证探针），用 FastAPI 提供 REST + WebSocket；路径探测做成独立模块，探测顺序为「注册表 → 已知登记文件 → 常见目录扫描 → 人工兜底」。

网络层交给 Tailscale：电脑和手机各装一次、登录同一账号，服务用电脑的 Tailscale IP 固定访问。

手机上沿用 `afu-ledger` 的技术栈与代码约定（Kotlin + Compose + MVVM、按功能分包、单文件 ≤300 行、UI 不直接访问数据层），三个游戏页用底部导航切换。

任务执行复用已验证的三种触发方式，放在电脑端做适配器与互斥队列；状态来源分别是 MAA 的 `reportStatus`、BetterGI 的日志、M7A 的 `runs/<id>.json` 与退出码。
