# 变更：手机端真机验证与出门场景修复

## 动机

界面重做的代码改完之后，只用「编译通过」验收过，**没有在任何真机上跑过**。
把 APK 装到真实手机上、用 5G 流量走公网（Tailscale Funnel）测了一遍，
发现了几类只靠编译发现不了的问题：

1. **带 `https://` 的地址被补上了 `:8765`** —— normalize 在 https 地址上也补端口，
   而 Funnel 走 443，补了端口反而连不上。表现为「明明能连却一直超时」。
2. **配对码输到地址框里** —— 地址被污染后界面没有任何提示，用户很难发现。
3. **连接失败只弹一个 toast** —— 一闪就没，而且容易被输入法挡住；
   用户最需要的恰恰是「照着提示去排查」。
4. **错误提示把主机名截断成 `https`** —— 同一个 `substringBefore(':')` 的坑犯了两次。
5. **连接页默认假设用户在家** —— 搜索按钮写着「仅局域网」，
   对出门在外的人毫无用处，页面下半还留着一大片空白。
6. **数据文件损坏会直接崩溃** —— DataStore 没有 `corruptionHandler`，
   文件一旦损坏 APP 启动即崩，用户只能卸载重装。

## 范围

在范围内：

- 手机端连接页重写：出门在外（Tailscale / 公网）作为主要路径，局域网作为次选
- 连接与配对的进行中状态、常驻失败原因（取代只弹 toast）
- 地址规范化：https 不补端口、错误提示正确解析主机名
- DataStore 损坏自愈
- 真机端到端验证记录

不在范围内：

- 服务端接口改动（本次全部是手机端）
- 游戏页、底栏的进一步改版（上一轮已做）
- 推送通知、后台保活

## 方法

连接页按「你现在在哪」组织，而不是按「技术实现」组织：
先给一个通用的地址输入 + 连接按钮，再单独给「在同一个 WiFi 下？」这一小节，
最后给「出门在外连不上？」的帮助卡片。这样两种场景的用户都能找到自己的路。

错误提示按地址类型（Tailscale / 家宽 / 公网 HTTPS / 其它）给出**不同的排查步骤**，
而不是统一一句「连接失败」。
