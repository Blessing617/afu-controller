# 设计：双端界面重做

## 1. 为什么要有独立的 design-system 能力

上一轮（`polish-ui-and-mobile-ux`）已经定过配色 token，但只定了**颜色**。
形状、字阶、按钮质感、动效曲线仍然散落在 `theme.py` 的 QSS 字符串、
`tokens.py` 的常量、`Theme.kt` 的 Color 列表和各个 Composable 里。
结果是「同一套色」但「不是同一套东西」——手机端的 Material 组件是最好证据。

所以这次把 token 提升为**两端共同遵守的接口**：

- 唯一来源仍是 `desktop/tokens.py` 与 `android/.../ui/Theme.kt` 两份文件（沿用既有约定，
  不引入代码生成），但两文件必须在**同一组数值**上一致，且由脚本比对。
- 新增 `scripts/check_design_tokens.py`：解析两侧 token，逐项比对，不一致即失败。
  这比「记得同步」可靠。

> 不选「代码生成单一源」：桌面端是 Python、手机端是 Kotlin，生成器要额外维护模板与构建钩子，
> 收益只有「少改一处」，代价是一个新工具链。比对脚本足够。

## 2. 配色：深海奶油糖果

浅色（默认）：

| 角色 | 值 | 说明 |
|---|---|---|
| 背景 | `#FFF6EA` | 奶油暖白，代替现在的冷灰 `#F5F7FA` |
| 卡片面 | `#FFFFFF` | 纯白卡浮在奶油底上，靠明度差分层，不描边 |
| 次级面 | `#FFF1E0` | 卡内分组块、输入框底 |
| 主色 | `#3A6FF0` | 鲸鱼蓝（比现有 `#4D8DFF` 更深、更稳） |
| 主色深 | `#2750C8` | 按压态 |
| 强调 | `#FF7E6B` | 珊瑚糖果，用于「复制地址」「开始」等关键动作 |
| 成功 / 警告 / 危险 | 沿用 `#3BA55D` / `#E0A030` / `#E5484D` | 状态色不改，避免语义漂移 |
| 文字 | `#1B2436` | 比现 `#1A2230` 略偏蓝，配奶油底更柔 |
| 次要文字 | `#6B7488` | |

深色（深夜海沟）：

| 角色 | 值 |
|---|---|
| 背景 | `#0D1526` |
| 卡片面 | `#16213A` |
| 次级面 | `#1D2A47` |
| 主色 | `#6D93FF`（深底上提亮，保证对比度） |
| 文字 | `#EDF2FF` / 次要 `#94A3BF` |

**和阿福记账的区分**：阿福记账是冷白底 + 亮天蓝 + 纯胶囊 + 极简留白；
本方案是**暖奶油底 + 更深的鲸鱼蓝 + 珊瑚强调 + 大圆角（22px）卡片 + 鲛人质感装饰**，
并保留深色主题。两套放在一起不应被认成同一个 App。

## 3. 形状与质感

- 卡片圆角 22px（现 14），控件圆角 999（胶囊），小标签 12。
- 按钮三种：`primary`（主色填充 + 白字 + 底部 2px 深色「厚度」形成糖果感）、
  `soft`（次级面填充 + 主色文字）、`ghost`（透明 + 悬停/按压才出面）。
- 果冻按压：按下时 `scale 0.96` + 亮度 -6%，松开以弹簧回弹（120–180ms）。
  桌面端：`QPushButton` 子类改 `QTransform` 缩放（在 `paintEvent` 里用缩放后的矩形绘制），
  **不用** `QGraphicsEffect`。
- 卡片不用投影：靠「奶油底 + 纯白卡」的明度差分层；深色主题靠卡片面比背景亮一档。
  这是性能取舍——阴影在 Qt 里对滚动区域是持续的合成开销。

## 4. 字体

- 标题 / 数字 / 时间：**猫啃珠圆体**（MaokenZhuyuanTi，SIL OFL 1.1）。
  选它的原因：字形圆、有中文字重、OFL 可随包分发，且**不是**阿福记账用的得意黑。
  备选：霞鹜文楷（LXGW WenKai，OFL），若珠圆体字重不足或包体过大则退到它。
- 正文：系统字体（Windows `Microsoft YaHei UI` / Android 默认），不打包，省体积。
- 时间、配对码、地址：等宽数字字形（圆体自带的 `tnum` 或 `Roboto Mono` 回退）。
- 授权：字体文件放 `assets/fonts/<name>/`，同目录放 `OFL.txt`，`THIRD-PARTY-NOTICES.md` 登记。
  若最终字体下载失败，退化为系统字体并在 README 如实说明——不假装有。

## 5. 动效曲线

统一三条：

| 名称 | 曲线 | 时长 | 用在哪 |
|---|---|---|---|
| `press` | 弹簧（`cubic-bezier(0.34, 1.56, 0.64, 1)`） | 140ms | 按钮按下 / 松开 |
| `enter` | 缓出 + 6% 位移 | 220ms | 页面切换、卡片进场 |
| `state` | 缓入缓出 | 150ms | 开关、选中态、颜色切换 |

约束：同一时刻只允许一条 `enter` 动画在跑；卡片进场总延迟 ≤ 80ms（不做整页 stagger）；
「减少动画」开启时全部退化为直切（已有规范，继续遵守）。
运行中的「呼吸光晕」只允许出现在「任务正在跑」的主按钮上，1.6s 循环，任务停止立即取消。

## 6. 桌面端结构

侧边栏（宽 200，可折叠到 64）：

```
[品牌区] 大肥鱼图标 + 「阿福代肝控制器」 + 一句副标题
[导航]   总览 / 依赖清单 / 设置（胶囊选中态，图标 + 文字，选中态底色为次级面 + 主色描边）
[底部]   版本号 + 当前地址来源徽标（Funnel / 局域网）
```

内容区统一页头：标题（圆体 22）+ 一句说明（次要文字 13）+ 右侧可选操作；
卡片统一 20px 内边距、16px 间距；滚动区底部留 24px 安全间距（避免最后一张卡被裁切）。

总览页信息分组（顺序即重要性）：

1. **服务**：状态胶囊（绿点 + 「运行中」）+ 右侧「停止服务」（ghost 危险色）；
   下方一行依赖结论。
2. **手机怎么连上这台电脑**：两个步骤竖排，
   - ① 填地址：主地址大号等宽 + 「复制地址」胶囊；来源徽标（公网固定 / 局域网）；
     主地址下不再重复列「其它可用地址」，改为一行「其它地址（N）」点开才展开的紧凑列表。
   - ② 填配对码：**状态胶囊**（已配对 / 未配对）+ 配对码（未配对时显示大号数字）
     + 「重新配对」按钮 + 有效期说明（次要文字）。
3. **三个游戏**：一张卡三行，图标 44 + 名称 + 状态胶囊。
4. **公网固定地址（出门在外用）**：Tailscale 四步检查表。

## 7. 手机端结构

- 顶栏：连接状态胶囊（绿点 + 已连接）+ 设置图标。
- 主区：画面卡（16:9，圆角 20，内嵌播放/刷新角标）→ 任务状态卡 → 主操作胶囊按钮
  （primary，高 56，占满宽，按压回弹）。
- 底栏：三个游戏图标 + 文字，选中态为「胶囊底 + 图标上浮 2dp」；中间不放按钮（避免学阿福记账）。
- 二级页：整屏滑入（已有规范），页面内统一用 `CandyCard` / `CandyButton` / `CandyChip`。

定时编辑（本次重点）：

- 点「添加时间」→ 底部弹出**自绘时间选择器**：小时与分钟两列滚动数字（大号圆体），
  上方实时预览「08:00」，一个珊瑚色「确定」胶囊、一个 ghost「取消」；
  不用 Material `TimePicker`。
- 星期选择：七个圆形/胶囊按钮横排（一 二 三 四 五 六 日），多选，选中态主色填充。
- 已添加时间点：一排胶囊 chip（时间 + 删除 ×），点 chip 二次进入选择器编辑；
  不再用 `AssistChip` 的默认样式。
- 删除确认：自绘 `CandyDialog`（圆角卡 + 两个胶囊按钮），不用 `AlertDialog` 默认外观。
- 功能完全等价：最多 8 个、总开关、断网本地暂存、关开关时的「同时停止」询问、
  「下次运行」提示。

## 8. 性能策略

- 桌面端：所有页面结构在启动时建好，切页只做显隐 + 透明度/位移动画；
  动画用 `QPropertyAnimation`（不阻塞事件循环），单次不超过 260ms；
  滚动区里不放 shadow effect。
- 手机端：装饰性渐变用 `Brush.linearGradient` 静态画，不用无限动画；
  列表项 `key` 稳定，避免整表重组；图片解码仍在后台线程（既有约束）。
- 两端都遵守既有 `performance` 预算；手机端必须 `assembleRelease` + `adb install -r` 后测，
  不拿 debug 数据下结论（`app/build.gradle.kts` 里已写明 debug 帧耗时虚高）。

## 9. 风险

| 风险 | 处理 |
|---|---|
| 字体下载不到 / 体积过大 | 退到霞鹜文楷；再不行退化系统字体并如实说明 |
| 大圆角 + 奶油底在小窗口下显拥挤 | 默认窗口 960×700、最小 860×600（参考 MAA 的量级，内容不多时不撑满屏），超出走滚动 |
| 自绘控件改坏输入行为 | 定时编辑只替换呈现层，状态与保存调用沿用现有 `vm.saveSchedule`，逐个场景回归 |
| QSS 全局改动波及依赖清单/设置页 | 两页一并纳入验收，不允许「只改总览」 |
