# 变更：编排能力（总编排 + 局部编排）

## 动机

现在的编排器只能执行**三套写死的一条龙**：MAA 的 `LinkStart`、BetterGI 的
`--startOneDragon`、三月七的 `daily`。用户实际想要的是两件事：

1. **总编排**：「今晚先方舟、再原神、最后星铁」或者「今天只跑原神和星铁」，
   顺序自己定，不用坐在电脑前一场一场点。现在做不到——三个游戏是三个独立的
   开始按钮，跑完一个得手动点下一个。
2. **局部编排**：三个引擎本身都是多功能的（MAA 有基建/公招/商店/刷体力，
   BetterGI 有一条龙配置和多个任务组，三月七有 27 个任务），
   现在只暴露了「一键」，用户没法说「今天只收菜不刷体力」。

实测三者的细粒度能力差别很大，这决定了设计：

| 引擎 | 枚举能力 | 实现方式 | 实测证据 |
|---|---|---|---|
| 三月七 | `m7a.exe --list --json` → **27 个任务**（含中文名） | 命令行直接传 task id | 已实跑，返回完整 JSON |
| MAA | 无枚举接口，但配置里 `TaskQueue` 有 `TaskType` + `IsEnable` | 写回 `config/gui.new.json` | 已读取实际配置内容 |
| BetterGI | 无枚举接口，子任务是 UUID 键 | 写回 `User/OneDragon/*.json` 的 `TaskEnabledList` | 已读取实际配置内容 |

## 范围

在范围内：

- **总编排**：一张「任务链」，由若干步骤组成，每步是一个游戏 + 一组子任务；
  顺序可调整、可增删、可启停；一键从头跑到尾。
- **局部编排**：每个游戏的步骤里可以选具体子任务（如「只跑基建 + 公招 + 商店」），
  选择结果**写回引擎自己的配置文件**，用引擎本来就读的字段（`IsEnable` / `TaskEnabledList`），
  不改引擎源码、不注入。
- **能力自报**：每个引擎提供一个「我能做什么」的清单。三月七从 `--list --json` 实时取；
  MAA / BetterGI 读配置得出；都拿不到时退回内置的静态清单，保证界面永远有东西可选。
- **失败策略**：默认「失败跳过继续」，跑完整条链后给出总结（哪几步成功、哪步失败）。
- **执行状态**：任务链作为一个整体显示进度（第 2/3 步 · 原神），每一步的日志分开。
- **手机端编辑**：任务链在手机 APP 里编辑（拖动排序 / 增删 / 勾选子任务），
  保存到电脑端并持久化。

不在范围内：

- **定时 / 周期任务**（每天 8 点自动跑）：用户明确说这次先不做，列入后续。
- **并行执行**：仍然串行，一步跑完再跑下一步（前台键鼠互斥是硬约束，不能破）。
- **跨引擎的自定义脚本**：不引入 JS/Python 脚本沙箱，只做「选步骤 + 选子任务」。
- **修改引擎的深层参数**：比如 MAA 刷哪一关、BGI 用哪套配队。只做「开/关子任务」，
  参数沿用用户在各引擎里已配好的值。
- **在电脑端编辑任务链**：这次只做手机端编辑，电脑端只读展示当前链。

## 方法

新增一个 `orchestration` 能力：服务端保存「任务链」配置（JSON），把每一步翻译成
对应引擎的「能力开关 + 启动参数」，写回引擎配置后按顺序启动；执行引擎复用现有的
`TaskRunner`，但外层加一层链式调度器负责推进步骤、处理失败策略、汇总结果。
手机端新增「编排」入口，用列表编辑，底部一个「一键跑完整条链」。
