# 变更：定时执行整条任务链

## 动机

现在必须有人手动点「一键跑完整条链」。用户的典型场景是「每天早上出门前跑一遍」「晚上睡前跑一遍」——
人不在电脑前，或者忘了点，就白等一天。

MAA 早就有这个能力（`Timers.List` 一组时间点，各自可启用；另有按星期、强制启动、定时唤醒），
用户明确希望「参考 MAA 那种感觉」，并且要在**手机 APP 的编排界面**里配。

还有一个反向诉求：**关掉定时的时候，如果它正在跑，要能强关并把电脑上那些游戏/工具全部收掉**。
不能出现「关了开关，MuMu 还在后台占 12GB」这种情况。

## 范围

在范围内：

- **定时配置**：启用开关、若干时间点（HH:MM）、可选星期；持久化在电脑端。
- **到点触发**：触发动作就是「跑完整条任务链」，与手动点按钮完全一致（同一套编排逻辑）。
- **互斥**：链正在跑时到点，本次跳过并记录，不排队、不打断。
- **手机端编排页**：新增「定时」卡片，可开关、加/删时间点、选星期、看到「下次运行时间」。
- **关掉定时**：保存为关闭；如果那一刻**正在跑由定时触发的链**，提供一次性强停：
  停链 → 停当前任务 → 关掉所有游戏与工具进程。
- **错过不补跑**：电脑关机/休眠期间错过的时间点，恢复后不补跑（半夜补跑比不跑更糟）。

不在范围内：

- **定时唤醒电脑**（MAA 的 `ScheduledWakeUp`）：需要改电源策略，风险大，这次不做。
- **多个不同任务链**：仍然只有一条链，定时只是决定「什么时候跑它」。
- **按天单独配置不同的链**（周一只跑原神、周二只跑方舟）：这次不做，要做的是「时间点 × 星期」。
- **执行前的倒计时确认**（MAA 的 `NotifyBeforeScheduledStart`）：不做通知，只在编排页显示下次时间。
- **电脑关机时也能跑**：做不到，也不试图做。

## 方法

1. 服务端加一个 `core/scheduler.py`：后台线程每分钟检查一次「现在是不是某个启用的时间点」。
2. 触发时直接调用现有的 `ORCH.start(load_chain())`，不新增执行路径——这样失败策略、进度广播、
   清理规则全部沿用。
3. 配置存在 `data/schedule.json`（与 `chain.json` 并列），手机端通过
   `GET/PUT /api/schedule` 读写。
4. 手机端在编排页加一张「定时」卡片；关闭开关时如果有定时触发的运行在进行，弹一次确认，
   确认后调 `POST /api/schedule/stop` 做强制停止 + 全量清理。
5. 记录「今天这个时间点已经跑过」，避免同一天重复触发（服务重启也不会重跑）。
