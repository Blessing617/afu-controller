# Delta：desktop-shell

## ADDED Requirements

### Requirement: 界面视觉与导航结构

电脑端应用 SHALL 采用**侧边栏导航 + 内容区卡片**的结构，而不是把所有信息堆在同一个窗口里。
应用 SHALL 提供深色与浅色两套主题，并跟随系统设置。
应用 SHALL NOT 使用操作系统默认控件外观（如 Windows 经典按钮、灰底窗体）。

#### Scenario: 启动后的第一屏

- GIVEN 用户双击应用
- WHEN 界面显示出来
- THEN 左侧有导航项（至少包含：总览、依赖清单、连接、设置）
- AND 右侧内容区以卡片形式组织信息
- AND 整体为深色或浅色主题之一，跟随系统

#### Scenario: 切换导航

- GIVEN 应用正在运行
- WHEN 用户在左侧点击「依赖清单」
- THEN 右侧切换到依赖清单内容
- AND 当前导航项有明确的选中态

#### Scenario: 窗口缩放

- GIVEN 用户把窗口拖大到接近全屏或缩小到最小尺寸
- WHEN 界面重新布局
- THEN 内容不错位、不重叠、不被截断
- AND 关键操作按钮始终可见

### Requirement: 桌面端应用图标

应用 SHALL 拥有自己的图标，用于窗口标题栏、任务栏与可执行文件本身。
图标 SHALL 为项目原创矢量图形，与手机端使用同一套品牌视觉。

#### Scenario: 任务栏与任务管理器

- GIVEN 应用正在运行
- WHEN 用户查看任务栏图标或任务管理器
- THEN 显示的是本项目图标，而不是 Python 或系统默认图标

#### Scenario: exe 文件图标

- GIVEN 用户拿到打包好的程序目录
- WHEN 在资源管理器里查看 `游戏编排器.exe`
- THEN 显示本项目图标

### Requirement: 状态可读性

关键状态（服务运行中 / 已停止 / 启动失败、各游戏是否可用）SHALL 用颜色与图形共同表达，不只靠文字颜色区分。
配对码 SHALL 以足够大的字号显示，便于在手机上照抄。

#### Scenario: 区分状态

- GIVEN 服务处于「运行中」与「已停止」两种状态
- WHEN 用户分别查看
- THEN 两种状态在颜色与图形上都不同
- AND 不依赖仔细读文字就能分辨

#### Scenario: 照抄配对码

- GIVEN 界面显示 6 位配对码
- WHEN 用户拿着手机准备输入
- THEN 配对码字号足够大、字符间距清晰，不会把 0 和 O、1 和 l 看混

### Requirement: 界面不冻结

应用 SHALL 保证界面在后台执行耗时操作（路径探测、服务启动、隧道建立、依赖检查）期间保持响应。
界面 SHALL 在耗时操作进行中显示进行状态，而不是无反馈地卡住。

#### Scenario: 重新探测期间

- GIVEN 用户点击「重新探测」
- WHEN 探测正在扫描磁盘
- THEN 窗口仍可拖动、可切换导航
- AND 有明确的「探测中」指示

#### Scenario: 服务启动中

- GIVEN 用户刚启动应用
- WHEN 服务还没就绪
- THEN 界面正常显示并给出进度提示
- AND 不出现白窗或无响应
