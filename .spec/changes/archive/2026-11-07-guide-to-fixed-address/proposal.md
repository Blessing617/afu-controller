# 变更：固定地址的获取引导

## 动机

用户连续两次指出同一个痛点：

> 「我现在都不知道电脑地址从哪来」
> 「这个 tailxxxxxx 这一串怎么来的你有好好教学吗」
> 「我是注册账户点击什么的才得到，你这些不管？」

把问题摊开看，之前的界面犯了三个错：

1. **假装地址凭空就有**
   界面上直接显示一个 `https://xxx.ts.net`，但没说这是用户注册 Tailscale、
   安装、登录、开 Funnel **四步之后**才出现的东西。
   新用户从零开始时根本没有这个地址。

2. **cloudflared 的临时地址抢占主位**
   连接页显著位置放着 cloudflared 的 `https://xxx.trycloudflare.com`，
   标题还叫「公网隧道」。用户照着填，结果那个地址每次重启都变，根本连不上。
   **它和「固定地址」完全是两码事，不该出现在用户路径上。**

3. **拿不到时不告诉用户为什么**
   Funnel 信息需要管理员权限读取，拿不到时界面只说「需管理员权限查看」，
   没告诉用户这意味着什么、该怎么办。

## 范围

在范围内：

- 连接页改成「四步检查表」：注册 / 安装 / 登录 / 开启 Funnel，
  每步自动检测并显示做没做
- 地址出现后大字显示 + 一键复制
- 把 cloudflared 临时隧道从连接页移到设置页，并标明「地址会变」
- 程序启动时自动读取一次固定域名并缓存，普通权限下也能显示
- README 补「这个网址到底是怎么来的」完整四步

不在范围内：

- 代替用户完成注册、安装、登录、Funnel 授权（这些必须用户自己在浏览器点）
- 手机端改动

## 方法

关键认知：**地址是 Tailscale 给的，不是本程序生成的。**
所以界面的职责是「检查每一步做没做、没做就告诉用户点哪里」，
而不是假装地址存在。

`tailscale status --json` 与 `tailscale funnel status` 都需要管理员权限
（走 Administrators 保护的命名管道）。因此：

- 程序启动时（通常已是管理员）读一次地址存进配置
- 之后即使降权，也能从缓存显示正确地址
- 拿不到时，四步检查表会指出卡在哪一步
