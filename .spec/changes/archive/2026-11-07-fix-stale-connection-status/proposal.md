# 变更：修复「已连接」状态不刷新

## 动机

实机发现：手机 APP 明明显示「已连接」，但电脑端服务其实已经停了；只有退出 APP 重进才会变成未连接。

原因是 APP 只在两个时机更新连接状态——启动时的 `tryConnect` 和用户手动重连——连上之后没有任何探活。轮询循环只在「有任务在运行」时才发请求，空闲状态下完全不碰电脑端，于是电脑端消失多久都不会被发现。

`connection` 规格里「连接断开 → 界面状态变为已断开」这条 scenario 一直存在但没真正实现。

## 范围

在范围内：

- 空闲时也周期性探活（5 秒一次 `/api/health`），失败即标记「已断开」
- `refreshAll` 与画面请求的网络层失败同样触发断开判定
- 电脑端恢复后由既有的自动重试逻辑重连，并恢复画面刷新

不在范围内：

- 连接状态的界面样式调整
- WebSocket 作为连接状态来源
- 重连退避策略优化（仍是固定 5 秒）

## 方法

`AppViewModel.startPolling()` 的循环里区分两种节奏：有任务时 3 秒拉一次状态，空闲时 5 秒打一次健康检查。任一请求出现网络层失败（非 401）就调用 `markDisconnected()` 把 `connected` 置 false，界面立即变成「已断开」，既有的 `startAutoRetry` 会继续每 5 秒尝试重连。
